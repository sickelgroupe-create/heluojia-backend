# 数据库文件

**全新部署按顺序导入 01 → 02 → 03；不要把目录内所有 SQL 通配执行，也不要向现网非空库导入。**

| 文件/目录 | 用途 |
| --- | --- |
| `00-create-database.sql.example` | DBA 创建数据库和专用账号的模板，先改密码 |
| `01-schema.sql` | 发布版本全部 112 张表的结构、索引和字段，无现网数据 |
| `02-system.sql` | 管理菜单、岗位权限、字典及基础配置；管理员初始禁用、无通用密码 |
| `03-catalog.sql` | 七款正式商品、固定零售价、页面及业务配置、默认仓库和零库存 |
| `bootstrap/` | 程序启动需要的 24 份 SQL，Maven 自动打包；无需手工重复导入 |

推荐运行 `deploy/init_database.py`：它先检查目标库为空，再按顺序导入，并让部署者设置 `admin` 密码。拒绝向已有表的数据库写入。具体命令见部署说明。

库存未从现网复制：清空订单后保留现网“已占用库存”会导致数量不一致，因此新安装库的库存全部为 0。登录后台后按实际盘点量入库。现网 0.01 元测试商品、客户及订单、会话、发放优惠券、客服记录、收款账户和管理员密码均不包含在公共 SQL 中。券模板/限时活动也不复制，避免新环境误启活动。

完整私密迁移库另行交接，保留原订单金额与历史企业订单。迁移时停写后重新取得同一时间点的数据库及上传文件快照，再恢复到空库；**不要叠加 02、03 初始化数据**。恢复后先更换目标环境连接配置、清理 Redis 登录缓存并验证文件路径，再开启对外服务。

Java `ShopService.init()` 仍保留历史字段升级逻辑，完整快照包含这些字段。以后修改数据库时，必须同步启动脚本/升级逻辑与 `01-schema.sql`，在空库验证后更新交付校验清单；只修改其中一处会造成新旧部署不一致。
